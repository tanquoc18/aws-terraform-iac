## 1. Cấu Trúc Cụm K3s (1 Control Plane + 1 Worker)

- **Phiên bản ghim cố định:** K3s **`v1.35.1+k3s1`** (bản ổn định, còn hỗ trợ chính thức).
- **Tự động nhận diện mạng Flannel:** Tự động phát hiện network interface chính xác qua `ansible_default_ipv4.interface` (tương thích cả `ens5` lẫn `eth0` trên AWS EC2).
- **K3s Server (Control Plane):**
  + IP Private: `10.0.1.x`, IP Public: `<SERVER_EIP>`.
  + Cờ khởi chạy: `--tls-san <SERVER_EIP> --tls-san <SERVER_PRIVATE_IP> --node-ip <SERVER_PRIVATE_IP> --write-kubeconfig-mode 600`.
  + **Hạn chế ServiceLB Placement:** Cấu hình `--node-label svccontroller.k3s.cattle.io/enablelb=true` trên Server node, đảm bảo Traefik Ingress và LoadBalancer chỉ mở public entrypoint tại Server node.
  + Kubeconfig admin được bảo vệ nghiêm ngặt bằng phân quyền `mode: 0600`.
- **K3s Worker Node:**
  + IP Private: `10.0.1.y`.
  + Kết nối về Server qua đường nội bộ: `K3S_URL=https://<SERVER_PRIVATE_IP>:6443`.
  + Gắn token xác thực: `K3S_TOKEN` từ `/var/lib/rancher/k3s/server/node-token` (ẩn hoàn toàn trong log bằng `no_log: true`).
  + Cấu hình `--node-label svccontroller.k3s.cattle.io/enablelb=false` để chặn ServiceLB chiếm cổng trên Worker.
  + Chiều Inbound Internet bị chặn 100% bằng Security Group Chaining.

## 2. Cấu Hình Tin Cậy Private Registry (`registries.yaml`)

Cả Server và Worker đều được Ansible tự động cấu hình file `/etc/rancher/k3s/registries.yaml`:

```yaml
mirrors:
  "hub.<HARBOR_EIP>.nip.io":
    endpoint:
      - "https://hub.<HARBOR_EIP>.nip.io"
configs:
  "hub.<HARBOR_EIP>.nip.io":
    tls:
      ca_file: "/etc/rancher/k3s/harbor-ca.crt"
```

Đồng thời ánh xạ `hub.<HARBOR_EIP>.nip.io` sang IP nội bộ `10.0.2.x` trong `/etc/hosts` giúp cụm K3s tải image trực tiếp qua hạ tầng mạng nội bộ VPC với chứng chỉ CA đã được xác thực an toàn.

## 3. Lệnh Kiểm Chứng Cụm K3s Sẵn Sàng (2 Nodes Ready)

```bash
# 1. Kiểm tra trạng thái các Nodes
kubectl --kubeconfig /tmp/kubeconfig get nodes -o wide
# Kỳ vọng:
# NAME         STATUS   ROLES                  AGE   VERSION        INTERNAL-IP   EXTERNAL-IP
# k3s-server   Ready    control-plane,master   ...   v1.35.1+k3s1   10.0.1.x      <SERVER_EIP>
# k3s-worker   Ready    <none>                 ...   v1.35.1+k3s1   10.0.1.y      <none>

# 2. Kiểm tra toàn bộ Pods hệ thống
kubectl --kubeconfig /tmp/kubeconfig get pods -A
# Kỳ vọng: CoreDNS, Traefik, Local-path-provisioner đều ở trạng thái Running

# 3. Thử nghiệm kéo image từ Harbor ÉP CHẠY TRÊN WORKER NODE (Khớp Manifest TV2)
# Chú ý: TV2 sử dụng workload Deployment/Service 'song-api' và Migration Job 'song-migrate-<release-id>'.
# Dưới đây là pod mẫu kiểm tra khả năng pull image bảo mật qua digest và gán vào Worker bằng nodeSelector bàn giao:
cat <<EOF | kubectl --kubeconfig /tmp/kubeconfig apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: test-pull-worker
  namespace: default
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: worker
  imagePullSecrets:
    - name: harbor-pull
  containers:
  - name: test-container
    image: hub.<HARBOR_EIP>.nip.io/<project>/song-management@sha256:<IMAGE_DIGEST>
    command: ["sleep", "3600"]
EOF

kubectl --kubeconfig /tmp/kubeconfig get pod test-pull-worker -o wide
# Kỳ vọng: Status = Running, NODE = k3s-worker (Chứng minh Worker kéo image thành công từ Harbor)
```
